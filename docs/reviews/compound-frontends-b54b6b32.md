Review of `origin/compound-boilerplate`, commit `b54b6b32d8f12c3346b99076f938fab767a1888d`, against merge base `7944bdd63f2f4af6b6e04837563b4fd04a9cc0f0`.

The supplied workspace was clean and pointed at `8b231dc1` (the same commit as `origin/main`), which does not contain this conversion. I located the conversion in the existing remote-tracking ref and reviewed an archived snapshot. These findings apply to that snapshot, not to `origin/transactions` or an unseen newer revision. The initial review changed no repository files. This report and MEMORY.md were subsequently saved at the user’s explicit request.

I would hold this conversion before merging. It has current correctness regressions as well as gaps in the frontend contract needed for later backend transactions. Missing backend begin/end hooks themselves are outside this review's requested scope; the concerns below are about frontend behavior and whether those hooks could be added without another frontend redesign.

Current correctness findings, ordered roughly by impact:

1. **[P1] Read-only export enforcement uses the export from before the leading PUTFH.** [nfs4_compound_vfs.c:2079](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2079), [decode at line 2971](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2971).

   The eligibility scan calls `nfs4_rofs_gate(req, argop)` for the whole run before decoding its leading PUTFH. The gate reads `req->export_id`, while the early unwrap only populates the local `seq_export`. A new wire COMPOUND initializes `req->export_id` to zero, and export zero passes the RO check. Thus `PUTFH(read-only-export-directory), CREATE(...)` can be accepted as a VFS sequence; decoding establishes the real export only after all the policy checks, and CREATE then reaches the writable backing filesystem. The same problem affects other admitted mutations. Check export policy against the actual per-op current/saved export context before executing each operation.

2. **[P1] Converted READ and WRITE bypass reboot grace.** [nfs4_compound_vfs.c:2544](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2544), [authorization helper:1705](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L1705).

   Both original handlers call `nfs_recovery_io_check()` before permitting I/O. Neither the sequence's READ/WRITE admission nor `nfs4_vfs_io_authorize()` does. The checks elsewhere in this file are for LOCKT, size-changing SETATTR, and OPEN; they do not cover READ/WRITE. A simple PUTFH + anonymous READ/WRITE can therefore perform I/O during the interval when the old handlers return `NFS4ERR_GRACE`, before potentially conflicting locks have been reclaimed. Factor the shared entry checks into a common execution-time gate.

3. **[P1] A second PUTFH can authorize SETATTR against one file and apply the request to the wrong file.** [nfs4_compound_vfs.c:2148](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2148), [authorization:3012](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L3012), [second PUTFH encoding:3065](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L3065).

   A later PUTFH neither sets `cur_moved` during the scan nor updates `cur_fh/cur_fhlen` during construction. The VFS cursor nevertheless moves to that later handle. For `PUTFH(A), PUTFH(B), SETATTR(size, stateid-for-A)`, the SETATTR authorization compares the stateid with A, accepts it, and passes A's open handle into the operation: A is truncated even though B is the current filehandle. With a special stateid, share-deny checks consult A while the operation acts on B. Track the actual current object, or defer authorization until that operation executes.

4. **[P1] ALLOCATE/DEALLOCATE lose the stateid-to-current-filehandle check even without a second PUTFH.** [nfs4_compound_vfs.c:3507](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L3507).

   The original handlers call `nfs_state_check_write_for_fh()`; the compound version substitutes the generic I/O authorization helper, which checks access mode and principal but never compares the state's filehandle to the current filehandle. `PUTFH(B), DEALLOCATE(stateid-for-A)` can punch A rather than return BAD_STATEID. The injected type check even inspects B while the mutation uses A's handle. Preserve the operation-specific authorization contract instead of treating all stateid-bearing operations as interchangeable.

5. **[P1] SETATTR ignores attribute decoding failures and can apply a partial malformed request.** [nfs4_compound_vfs.c:3319](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L3319).

   `chimera_nfs4_unmarshall_attrs()` returns BADXDR for missing/trailing bytes and INVAL for invalid timestamps. The old `chimera_nfs4_setattr_apply()` checks that result; the compound encoder discards it and submits the partially populated `sattr`. For example, encode a valid SIZE followed by a truncated MODE value: SIZE has already been decoded when parsing fails, so the converted path can truncate the file and return success. Reject the decode before submitting the mutation, while preserving wire operation ordering for earlier valid operations.

6. **[P1] VERIFY/NVERIFY omit validation and compare a substituted ACL.** [nfs4_compound_vfs.c:3469](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L3469), [verification gate:1268](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L1268).

   The old dispatcher calls `verify_validate_mask()`; the new scan never does. The shared `chimera_nfs4_verify_status()` only marshals and compares, so unsupported/write-only attributes can become NOT_SAME or a successful NVERIFY instead of ATTRNOTSUPP/INVAL. A mutation after that NVERIFY can consequently execute when it should not. Also, GETATTR's ACL exclusion was not added to VERIFY: the executor strips `va_acl` before the gate, so VERIFY/NVERIFY of a real ACL compares against mode-derived attributes instead. Preserve mask validation and either retain an owned ACL or evaluate against the live attributes before stripping them.

7. **[P1] Reply-buffer failure is discovered after later mutations have executed.** [nfs4_compound_vfs.c:2928](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2928), [late check:1345](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L1345).

   The worst-case response-space check applies only when `stages_early` is set, and that flag only covers the xattr operations. GETATTR result allocation and the 8192-byte dispatcher floor are evaluated in the final fill loop, after the executor has run the full sequence. A run with limited remaining response space, GETATTR results and a later mutation can therefore mutate successfully and then report RESOURCE at an earlier operation. Streaming READDIR also consumes response space before preceding GETATTR results are filled, changing the allocation order. Reserve sufficient space for every admitted run or make these failure decisions before subsequent side effects.

8. **[P1] The late-failing LOCKT guard is missing for the newly added range mutations.** [nfs4_compound_vfs.c:2456](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2456), [range admission:2460](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L2460).

   LOCKT deliberately sets `may_fail_late`, since its claim conflict is evaluated only when filling the reply. WRITE, SETATTR, CREATE and other mutations refuse to follow it. ALLOCATE, DEALLOCATE and WRITE_SAME do not. A conflicting LOCKT followed by a range mutation can change data and then produce a reply ending at LOCKT with DENIED. The mutation can target a different range from the conflicting lock, so its own VFS arbitration is not a substitute for stopping the sequence. Apply the guard consistently, preferably by moving LOCKT's judgment into execution.

9. **[P1] NFSv3 ACCESS no longer honors ACLs.** [nfs3_proc_access.c:208](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs3_proc_access.c#L208), [access evaluation:93](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs3_proc_access.c#L93).

   The old GETATTR requested `CHIMERA_NFS3_ATTR_MASK | CHIMERA_VFS_ATTR_ACL`. The replacement requests only the former, and compound attribute storage strips any ACL in any event. The unchanged completion then calls `chimera_vfs_access_check()` on the stripped attributes and falls back to mode bits. Named-user grants/denials are lost. The isolated probe confirms an explicitly denied UID changing from READ denied to READ granted after compound attribute storage. Use the compound ACCESS operation and its live-ACL `granted` result, retaining the full attributes needed for the NFSv3 reply.

10. **[P2] 64-bit range completion lengths are truncated to 32 bits.** [vfs_compound.c:2463](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2463), [WRITE_SAME:2538](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2538), [client_copy_range.h:38](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/client/client_copy_range.h#L38).

    COPY_RANGE and WRITE_SAME receive a 64-bit result but store it in the 32-bit `written` field; their client completion adapters also use 32-bit locals. A successful 4 GiB operation returns zero, and larger results wrap. NFSv4 WRITE_SAME copies that truncated value into its 64-bit wire count. The probe reproduces 4294967296 becoming 0. Carry a 64-bit result through the entire path.

11. **[P1 API defect] GETHANDLE does not preserve a single reference owner.** [vfs_compound.c:3250](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L3250), [CLOSE:3264](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L3264), [cleanup:221](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L221).

    GETHANDLE unconditionally copies the cursor into an owning `out_handle`. For a PUTHANDLE cursor this converts a borrowed reference into an owned one without acquiring a reference. Repeated GETHANDLE creates multiple owners of the same reference. CLOSE releases the handle but leaves earlier `out_handle` slots pointing at it, so cleanup releases it again. Instrumented execution confirms one erroneous release for borrowed PUTHANDLE/GETHANDLE/free and two releases for PUTHANDLE/GETHANDLE/CLOSE/free. Current FUSE callers use a narrower OPEN_CURRENT/GETHANDLE pattern, so these particular compositions are API defects rather than demonstrated FUSE wire exploits. Define borrowing, transfer and CLOSE invalidation consistently before SMB starts composing these operations.

Frontend architecture and retry-readiness findings:

12. **[P1 for the proposed transaction contract] NFSv4 completion ignores compound-level failure.** [nfs4_compound_vfs.c:1311](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L1311).

    The completion inspects individual op statuses but never calls `chimera_vfs_compound_status()`. If a future backend finishes with EAGAIN after every op returned OK, this callback would fill successful replies, install OPEN state, release write payloads and continue or complete the wire request. This is exactly the finish-time failure the proposed design must support. Establish a separate finish outcome now and exercise it using a fake finish hook; per-op success must remain tentative until that outcome is accepted.

13. **[P1 for retry safety] FUSE READDIRPLUS callbacks publish shared state before finish, and reset does not undo it fully.** [fuse_proc_dir.c:175](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/fuse/fuse_proc_dir.c#L175), [grant acquisition:185](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/fuse/fuse_proc_dir.c#L185), [unwind:262](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/fuse/fuse_proc_dir.c#L262).

    Entry callbacks insert/increment globally visible nodes and create or rearm VFS coherence claims while the sequence runs. Reset decrements lookup counts, but only drops grants if the node is retired. For an already known inode, a newly armed/rearmed grant survives the aborted attempt. Other threads can also observe and interact with the claim before rollback. This violates the stated side-effect-free pre-completion callback requirement; an undo of lookup counts is insufficient. Stage node/grant publication until accepted completion, or design an explicitly attempt-scoped reservation mechanism that cannot become visible as committed state.

14. **[P1 for retry safety] Operation inputs and per-op reply marks are not a reusable attempt description.** [vfs_compound.c:2052](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2052), [exclusive reopen:2083](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2083), [NFS READDIR reset:432](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L432).

    OPEN resolution clears the stored create attribute masks in place. If the first attempt finds an existing object, then a finish conflict causes a retry which finds it absent, the original creation attributes have been lost. Separately, each NFS READDIR keeps its first attempt's absolute dbuf mark. With two READDIRs, a retry whose first page grows followed by resetting the second page to its old mark overwrites part of the new first page. There is no whole-attempt cleanup that also resets effects of later operations when a retry stops earlier. Separate immutable request arguments from per-attempt results; rewind the whole response arena once per attempt and establish fresh per-op marks within it.

15. **The conversion does not yet establish the requested frontend coverage or compound boundary.** [NFS run boundary:322](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L322), [completion handing back to OPEN:1440](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/nfs/nfs4_compound_vfs.c#L1440), [existing SMB advancement:1095](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/smb/smb.c#L1095).

    SMB2, S3 and REST contain zero `chimera_vfs_compound_*` uses. NFSv3 converts only GETATTR, ACCESS, FSINFO, FSSTAT, PATHCONF and READLINK. Client READDIR, lsetattr and some `_at` paths remain direct. NFSv4 submits eligible runs, with OPEN and SECINFO ending a run and ACL/delegation/pNFS/stateful operations frequently falling back. OPEN's share reservation, state publication and possible truncate execute after that VFS compound has been freed. Consequently an OPEN/WRITE/CLOSE wire compound cannot become one backend transaction simply by adding backend begin/end callbacks.

    Keep one request-level compound identity across translations and protocol-only steps, and distinguish an execution segment from the compound's final commit boundary. If an operation genuinely must end a transaction, make that boundary explicit rather than silently deriving it from encoder limitations.

16. **The executor's fixed failure and credential model cannot represent SMB2 chains faithfully.** [vfs_compound.c:1667](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L1667), [existing SMB completion:1137](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/server/smb/smb.c#L1137).

    The executor stops at every first failure and binds one credential for the whole sequence. The existing SMB implementation deliberately advances after failures, with independent requests continuing and related requests inheriting protocol context; unrelated requests can resolve different sessions/trees. Mapping that chain 1:1 requires explicit dependency/failure policy and per-op effective context, or a shared transaction envelope around independently dispatched segments. Splitting at every such distinction loses the intended chain-wide transaction boundary.

17. **The result vocabulary discards information other frontends need.** [vfs_compound.c:2292](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2292), [CREATE dispatch:2947](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L2947), [attribute storage:1730](https://github.com/chimera-nas/chimera/blob/b54b6b32d8f12c3346b99076f938fab767a1888d/src/vfs/vfs_compound.c#L1730).

    Several callbacks throw away pre/post-operation attributes, namespace operations hardcode CHANGE/CTIME masks, and owned ACL results are unsupported. NFSv3 weak-cache-consistency replies need attributes captured atomically with the mutation; a following GETATTR cannot reconstruct the pre-state. SMB security information similarly needs the actual ACL. Make requested pre/post masks and ownership-safe variable-sized attribute results part of the generic API, rather than preserving these operations permanently outside compounds.

The advertised four-cursor model is also unfinished: `chimera_vfs_compound_step()` still derives implicit opens from an operation-type table, maintains `in_handle`, `handle_from` and cursor addressing simultaneously, and can replace explicitly supplied handles based on caller-reported flags. NFS duplicates the opening policy in `nfs4_vfs_open_for()`. This is a maintenance risk and leaves the documented claim that opening is fully explicit inaccurate. Choose one authoritative addressing/opening contract and test it before expanding the conversions.

Validation and practical limits:

- Compared the 65-file, approximately 13,000-line conversion diff with its merge base, inspected converted adapters and their previous handlers, and traced the relevant VFS, ownership, authorization and response paths. No full protocol conformance run was performed against this archived branch.
- Built an isolated C probe that includes the reviewed `vfs_compound.c`, links the available debug libraries for external symbols, and replaces handle release with a counter. It confirms the ownership compositions, 64-bit count truncation and ACL-loss effect described above; it is not an end-to-end backend test. Source: [compound-review-probe.c](compound-review-probe.c). Build/run script: [build_probe.py](/tmp/chimera-compound-review/build_probe.py). LeakSanitizer was disabled because it cannot run under this environment's tracing; the probe was compiled with AddressSanitizer.
- The new compound test is memfs-only and contains no GETHANDLE/SAVEHANDLE/RESTOREHANDLE/OPEN_CURRENT or EAGAIN tests. Existing per-op/model tests do not establish equivalence of the new encoder, particularly when fallback chooses the old implementation. Add a way to assert which path a test actually exercised.

Before merging, I would require differential tests of old/new frontend behavior for RO exports, grace, multiple PUTFHs, stateid mismatches, ACL ACCESS and VERIFY, malformed SETATTR, response-space exhaustion, LOCKT followed by range mutations, and 64-bit counts. Separately, inject a finish-time EAGAIN with all per-op statuses OK, retry a changed directory page and a changed OPEN lookup result, and assert that no reply, shared frontend state, ownership transfer or input consumption escapes the rejected attempt. Those tests can use a fake transaction backend and do not require implementing production backend transactions in this pass.
